数据存储

容器的生命周期可能很短，会被频繁地创建和销毁，容器销毁时保存在容器中的数据也会被清除。为了持久化保存数据，k8s 引入了 Volume 的概念。

Volume 是 Pod 中能够被多个容器访问的共享目录，它定义在 Pod 上，被 Pod 里的多个容器挂载到具体目录。Volume 的生命周期和 Pod 相关，与单个容器的生命周期无关，容器终止或重启时 Volume 中的数据不会丢失。

常见的 Volume 类型：

分类 类型 作用
基本存储 EmptyDir、HostPath、NFS 持久化保存数据
高级存储 PV、PVC 把存储和使用分离，屏蔽底层存储细节
配置存储 ConfigMap、Secret 存储配置信息和敏感信息

EmptyDir

EmptyDir 是 Host 上的一个空目录，在 Pod 被分配到节点时自动创建，无需指定宿主机目录。Pod 销毁时，EmptyDir 中的数据会被永久删除，一般用于临时空间或同一 Pod 内多个容器共享数据。

示例：nginx 把日志写入共享目录，busybox 实时读取日志。

HostPath

HostPath 把 Node 主机的实际目录挂载到 Pod，Pod 销毁后数据仍然保留在节点上。缺点是数据只存在当前节点上，Pod 被调度到其他节点后就无法访问原来的数据。

hostPath 的 type 取值：

type 说明
DirectoryOrCreate 目录存在就使用，不存在先创建
Directory 目录必须存在
FileOrCreate 文件存在就使用，不存在先创建
File 文件必须存在
Socket unix 套接字必须存在
CharDevice 字符设备必须存在
BlockDevice 块设备必须存在

说明：创建后访问 nginx 触发日志写入，然后到 Pod 所在节点的 /root/logs 目录就能看到日志文件。

PV 和 PVC

PV（PersistentVolume）是持久化卷，是对底层共享存储的抽象，一般由 k8s 管理员创建；PVC（PersistentVolumeClaim）是持久卷声明，是用户对存储需求的申请。

使用 PV/PVC 后职责分开：存储由存储工程师维护，PV 由 k8s 管理员维护，PVC 由用户维护。

PV

PV 关键参数：

  • capacity：存储容量，如 storage: 1Gi。
  • accessModes 访问模式：
    • ReadWriteOnce（RWO）：读写，只能被单个节点挂载。
    • ReadOnlyMany（ROX）：只读，可以被多个节点挂载。
    • ReadWriteMany（RWX）：读写，可以被多个节点挂载。
  • persistentVolumeReclaimPolicy 回收策略：
    • Retain：保留数据，需要管理员手工清理。
    • Recycle：清除 PV 中的数据（相当于 rm -rf）。
    • Delete：删除后端存储的 volume（常见于云存储）。
  • storageClassName：存储类别，指定类别的 PV 只能和请求该类别的 PVC 绑定。
  • status 状态：Available（可用，未被绑定）、Bound（已绑定）、Released（PVC 被删除后释放）、Failed（回收失败）。

PVC

PVC 关键参数：accessModes（访问模式，必须和 PV 匹配）、selector（采用标签对 PV 选择）、storageClassName（存储类别，只有设置了该类别的 PV 才能被选中）、resources.requests.storage（申请的容量）。示例中 selector 和 storageClassName 不填写，PVC 会按访问模式和容量自动匹配 PV。

Pod 中使用 PVC：

生命周期

  • 资源供应：管理员创建底层存储和 PV。
  • 资源绑定：用户创建 PVC，k8s 根据 PVC 的需求找一个满足条件的 PV 进行绑定；找不到时 PVC 一直处于 Pending，直到有匹配的 PV 出现。一个 PV 只能绑定一个 PVC。
  • 资源使用：Pod 通过 Volume 引用 PVC，挂载到容器内使用。
  • 资源释放：删除 PVC 后，对应的 PV 被标记为 Released，数据可能还保留着，不会立刻给其他 PVC 使用。
  • 资源回收：根据 PV 的回收策略（Retain/Recycle/Delete）处理遗留数据，回收完成后 PV 才能再次被绑定。

ConfigMap

ConfigMap 用来存储配置信息，可以把配置从镜像中解耦出来，通过挂载的方式注入到 Pod。

说明：ConfigMap 挂载后，每个 key 对应一个文件、value 就是文件内容；以文件方式挂载时，更新 ConfigMap 后容器中的值会同步更新。

Secret

Secret 和 ConfigMap 类似，用来存储敏感信息（密码、密钥、证书）。Secret 中的数据需要先经过 base64 编码。

说明：挂载到容器后会自动解码，直接看到明文；kubectl describe 只显示数据的字节数，不会显示内容。

安全认证

访问控制概述

k8s 的安全性主要体现在对访问 ApiServer 的客户端进行认证和鉴权。客户端分为两类：

  • User Account：独立于 k8s 之外的用户账号。
  • Service Account：k8s 管理的账号，为 Pod 中的进程访问 k8s 提供身份。

ApiServer 是访问和管理资源的唯一入口，任何请求都要经过三个流程：

  • 认证（Authentication）：鉴别客户端身份。
  • 授权（Authorization）：判断用户是否有权限对资源执行操作。
  • 准入控制（Admission Control）：对请求做更精细的补充校验。

认证管理

k8s 提供了三种客户端身份认证方式：

认证方式 说明
HTTP Base 认证 用户名:密码 经过 base64 编码后放在请求 Header 中
HTTP Token 认证 每个 Token 对应一个用户名，请求时在 Header 中携带 Token
HTTPS 证书认证 基于 CA 根证书签名的双向数字证书认证，安全性最高

HTTPS 认证的三个过程：证书申请和下发 → 客户端和服务端双向认证 → 协商密钥后加密通信。

注意：k8s 允许同时配置多种认证方式，只要其中任意一种认证通过即可。

授权管理

授权发生在认证成功之后，ApiServer 根据请求携带的用户和资源信息（用户、路径、动作）与授权策略比对，符合策略才允许执行。支持的授权策略：

  • AlwaysDeny：拒绝所有请求，一般用于测试。
  • AlwaysAllow：允许所有请求，相当于不授权（默认策略）。
  • ABAC：基于属性的访问控制。
  • Webhook：调用外部 REST 服务授权。
  • Node：对 kubelet 发起的请求做访问控制。
  • RBAC：基于角色的访问控制，kubeadm 安装方式的默认选项。

RBAC 的核心是描述「给哪些对象授予哪些权限」，涉及三个概念：对象（User、Group、ServiceAccount）、角色（一组权限的集合）、绑定（把角色和对象绑定）。RBAC 有 4 个顶级资源对象：Role、ClusterRole、RoleBinding、ClusterRoleBinding。

Role 和 ClusterRole

Role 只能对某个命名空间内的资源授权；ClusterRole 可以对集群范围内的资源、跨命名空间的资源、非资源类型授权。

rules 中的三个参数：apiGroups（API 组列表，如 “”、apps、batch）、resources（资源对象列表，如 pods、services、deployments）、verbs（操作方法列表，如 get、list、watch、create、delete）。新版本集群可以使用 rbac.authorization.k8s.io/v1，写法相同。

RoleBinding 和 ClusterRoleBinding

角色绑定把角色授予对象（User、Group、ServiceAccount）。RoleBinding 绑定的是命名空间内的权限；ClusterRoleBinding 在整个集群范围内授权。

说明：RoleBinding 也可以引用 ClusterRole，此时只在 RoleBinding 所在的命名空间内生效。常用做法是管理员预定义好一批 ClusterRole，然后在多个命名空间通过 RoleBinding 复用。

准入控制

通过认证和授权之后，请求还需要经过准入控制，所有准入控制器检查通过后 ApiServer 才会执行请求，否则拒绝。

常见准入控制器：

准入控制器 作用
NamespaceLifecycle 拒绝在不存在的命名空间创建资源，删除命名空间时清理其中所有对象
LimitRanger 对命名空间中的 Pod 做资源限制
ServiceAccount 自动为 Pod 设置 ServiceAccount
ResourceQuota 资源配额管理，确保命名空间配额不超标
DefaultStorageClass 为未指定 StorageClass 的 PVC 匹配默认存储类别
AlwaysPullImages 启动容器前总是拉取镜像

说明：准入控制器列表通过 ApiServer 启动参数配置，新版本集群使用 –enable-admission-plugins 指定。
