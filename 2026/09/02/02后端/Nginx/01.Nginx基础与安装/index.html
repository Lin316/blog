Nginx 概述

功能定位

Nginx 是一个高性能的 HTTP 服务器和反向代理服务器。

核心用途可概括为一句话：在用户请求与后端服务之间承担接入、转发与分发职责，并高效处理静态资源。

Nginx 高性能的原因

  1. 多进程模型：一个 master 主进程负责管理，多个 worker 进程并行处理请求，进程间相互独立。
  2. I/O 多路复用（epoll）：单个 worker 可同时监控大量连接，仅处理就绪的连接，避免为每个连接分配独立线程或进程。这也是要求 Linux 内核 2.6 以上的原因——epoll 自该版本起提供。

可以理解为：传统模型为每个连接分配一个处理单元，而 Nginx 由少量 worker 统一监听海量连接，显著降低了上下文切换与资源占用。

主要优势

优势 说明
高并发、低资源占用 多进程 + epoll 架构，单机可支撑数万并发连接
配置简单、扩展性强 模块化设计，可通过配置启用官方或第三方模块
高可靠性 master 监控 worker，worker 异常退出时可被重新拉起
热部署 修改配置、升级版本无需停机，平滑切换
开源免费 BSD 许可证，可免费商用，也可修改源码定制

安装目录结构

conf 目录中值得关注的文件：

  • nginx.conf：Nginx 核心配置文件，是后续所有功能配置的基础。

启动、停止与平滑管理

进程模型

启动后通过 ps -ef | grep nginx 可观察到两类进程：

  • master 进程：负责接收外部信号、监控 worker 状态，并在 worker 异常退出时重新拉起；
  • worker 进程：实际处理用户请求，进程间相互独立、地位平等。

管理员只需向 master 发送信号即可控制整个 Nginx，master 的 PID 记录于 logs/nginx.pid。

命令行控制

命令 作用
nginx 启动
nginx -s stop 快速停止
nginx -s quit 优雅停止（处理完当前请求后退出）
nginx -s reload 平滑重载配置
nginx -s reopen 重新打开日志文件（用于日志切割）
nginx -t 检查配置文件语法
nginx -v / nginx -V 查看版本 / 版本与编译参数
