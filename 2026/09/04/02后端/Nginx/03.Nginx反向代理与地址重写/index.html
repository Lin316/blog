Rewrite 概述

Rewrite 用于将请求 URI 改写为另一地址，典型场景包括旧域名跳转、URL 伪静态、路径简化等。该功能依赖 PCRE 正则库，由 ngx_http_rewrite_module 模块解析。

先区分两个易混淆的概念：

概念 浏览器地址 请求次数 性能
地址重写（Redirect） 发生变化 两次 较慢
地址转发（Forward） 不变化 一次 较快

常用指令

指令 作用
set 定义变量，如 set $username TOM;
if 条件判断（语法受限，仅限特定场景使用）
break 中断当前作用域内后续指令的执行
return 直接返回状态码、内容或 URL，后续指令不再执行
rewrite 通过正则改写 URI
rewrite_log 开启重写日志（输出至 error.log 的 notice 级别）

变量 含义 示例值

$request_uri 完整 URI（含参数） /server/index.html?id=10&name=zhangsan

break 指令

break 在 Nginx 中有两种形态，作用不同，使用时应加以区分：

  1. **独立指令 break;**（由 ngx_http_rewrite_module 提供）：终止当前 rewrite 处理阶段中后续指令的执行，位于 break 之前的指令生效，之后的指令不再执行；
  2. rewrite 的 flag（rewrite ... break;）：URI 重写后不再重新进入 location 匹配，仅在当前 location 内继续处理。

形态一：独立指令中断后续执行

执行说明：

  • 请求不带参数时，$args 为空，if 条件为 false，username 保持 TOM；
  • 请求携带参数时，username 先被设为 JERRY，随后 break 中断当前阶段处理，ROSE 的赋值被跳过，最终返回 JERRY。

形态二：rewrite 标志（与 last 对比）

访问 /rewrite/testabc 时：URI 被改写为 /test，但 break 使 Nginx 不重新匹配 location，仍停留在 /rewrite 块内处理，最终返回 404；若把 break 换成 last，Nginx 会重新匹配 location 并落入 /test 块，返回 test_success。

用法 改写后的行为 结果
rewrite ... last; 重新进入 location 匹配 可能落入其他 location 处理
rewrite ... break; 留在当前 location 继续处理 不跳出当前 location

实际场景：防盗链提示图（为什么这里必须用 break）

说明：rewrite 将 URI 改写为 /images/forbidden.png。若使用 last，Nginx 会重新匹配 location，而新 URI 仍以 .png 结尾，会再次命中当前正则 location 并再次执行 rewrite，形成循环，Nginx 达到重写次数上限后返回 500；使用 break 则在当前 location 内直接以 root 查找并返回提示图片。

if 指令

Nginx 的 if 与编程语言中的布尔判断不同：它没有独立的布尔类型，判定规则是”空字符串或 "0" 为假，其余为真“。具体分类如下：

条件写法 为 false 的情形 为 true 的情形
变量名：if ($param) 变量值为空字符串或 "0" 变量值非空且不等于 "0"
相等比较：if ($x = value) 两值不相等 两值相等
不等比较：if ($x != value) 两值相等 两值不相等
正则：if ($ua ~ pattern) / ~* 匹配失败 匹配成功
取反正则：if ($ua !~ pattern) / !~* 匹配成功 匹配失败
文件存在：if (-f $file) 文件不存在 文件存在
目录存在：if (-d $file) 目录不存在 目录存在
文件或目录存在：if (-e $file) 均不存在 任一存在
可执行：if (-x $file) 文件不可执行 文件可执行
取反判断：if (!-f $file) 等 原条件成立 原条件不成立

注意：Nginx 中字符串无需加引号（除非包含 }、; 等字符）；比较运算符 =、!= 前后需保留空格。

rewrite 指令

语法：rewrite 正则 替换内容 [flag];

flag 行为
last 重写后重新进入 location 匹配流程，可能落入其他 location
break 重写后仅在当前 location 内继续处理
redirect 返回 302 临时重定向，浏览器地址变化
permanent 返回 301 永久重定向，浏览器地址变化

对比 last 与 break 的差异：

  • 使用 last：访问 /rewrite/testabc 重写为 /test 后重新匹配 location，落入 /test 块并返回 test_success；
  • 改用 break：URI 虽被改写，但不会跳出当前 location，最终返回 404。

若替换内容以 http:// 或 https:// 开头，Nginx 直接向客户端返回重定向：

rewrite_log 指令

rewrite_log 用于输出 rewrite 指令的执行过程（正则是否命中、URI 被改写为什么），便于排查”rewrite 没生效””规则写错导致误跳转”等问题。

语法与位置：

项目 说明
语法 `rewrite_log on
默认值 off
位置 http、server、location、if

关键前提：rewrite 日志以 notice 级别写入 error_log，因此 error_log 的级别必须不高于 notice（即 debug/info/notice 均可）。若保持默认的 error 级别，notice 日志不会输出。

反向代理

正向代理与反向代理

正向代理 反向代理
代理对象 客户端 服务端
隐藏对象 客户端身份 后端服务器
典型场景 企业上网代理 流量网关、负载均衡入口

正向代理代替客户端发起请求，服务器只能感知代理地址；反向代理位于后端服务器之前，客户端只与 Nginx 交互，无法直接接触后端节点。

proxy_pass 指令

面试高频：proxy_pass 后是否添加 “/“？

  • proxy_pass 后不含 URI（仅协议与 IP:端口）时，请求 URI 原样转发；
  • proxy_pass 后含 URI（/ 或具体路径）时，location 匹配部分将被替换。

以 location /server 为例：

proxy_pass 写法 访问 /server/index.html 时后端接收 原因
proxy_pass http://192.168.200.146; /server/index.html 不含 URI，原样转发
proxy_pass http://192.168.200.146/; /index.html 含 /，替换 location 前缀

proxy_redirect 指令

作用与产生原因

反向代理场景下，后端返回 301/302 重定向时，响应头中的 Location（或 Refresh）往往指向后端自身的地址，例如写死的内网 IP、内部端口或上游主机名。客户端收到该响应后，会按 Location 再次发起请求，可能出现两种情况：

  • 客户端无法访问内网地址，重定向失败；
  • 客户端绕过 Nginx 直接访问后端，暴露内网节点。

proxy_redirect 用于修改被代理服务器响应头中的 Location 与 Refresh 字段，把后端返回的地址改写为客户端可访问的对外地址。

语法与位置

项目 说明
语法 proxy_redirect redirect replacement;
proxy_redirect default;
proxy_redirect off;
默认值 proxy_redirect default;
位置 http、server、location

三种写法：

写法 行为
proxy_redirect redirect replacement; 将响应头中匹配 redirect 前缀的地址替换为 replacement（支持变量与正则）
proxy_redirect default; 由 Nginx 依据当前 location 与 proxy_pass 自动推导替换规则，适用于常规代理配置
proxy_redirect off; 关闭替换，原样透传后端返回的地址

可配置多条 proxy_redirect，Nginx 按配置顺序匹配，命中第一条即生效。

安全隔离

反向代理的另一价值在于安全隔离：后端节点部署于内网，防火墙仅对外开放 Nginx 的 80/443 入口，外部无法直接访问应用服务器，从而降低被攻击面。

代理性能调优

先区分两个概念：

Buffer 缓冲 Cache 缓存
本质 数据中转区 数据副本
生命周期 请求处理完毕即释放 可长期复用
解决的问题 上下游传输速度不一致 重复请求直接命中，降低后端压力

指令 作用
