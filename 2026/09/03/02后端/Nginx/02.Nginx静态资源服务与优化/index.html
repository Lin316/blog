静态资源与动态资源

类型 示例 处理方
静态资源 html、css、js、图片、视频 Nginx 直接返回，性能极高
动态资源 报表、个人中心、购物车数据 需反向代理至 Tomcat/SpringBoot 处理

常规架构中，Nginx 负责静态资源与流量接入，动态请求转发给后端应用服务器，即”动静分离”。

listen：监听地址与端口

写法 含义
listen 127.0.0.1:8000; 仅监听本机回环地址 8000 端口
listen 127.0.0.1; 监听指定 IP 的全部端口
listen 8000; 监听所有网卡的 8000 端口
listen 80 default_server; 将该 server 指定为默认主机

default_server 的作用：同一端口存在多个 server 时，若请求域名均无法匹配，则交由默认主机处理。未显式指定时，使用配置文件中的第一个 server。

server_name：虚拟主机名

server_name 用于确定请求域名对应的 server，支持三种配置方式：

  1. 精确匹配：server_name www.itcast.cn www.itheima.cn;
  2. 通配符匹配：server_name *.itcast.cn www.itheima.*;（通配符仅可置于首段或尾段）
  3. 正则匹配：server_name ~^www\.(\w+)\.com$;（以 ~ 开头）

location：URI 匹配规则

location 决定请求 URI 交由哪个配置块处理，五种匹配方式：

写法 含义 特点
location /abc 普通前缀匹配 以 /abc 开头即匹配
location = /abc 精确匹配 要求完全一致
location ^~ /abc 前缀匹配并停止 命中后不再匹配正则
location ~ 正则 正则匹配 区分大小写
location ~* 正则 正则匹配 不区分大小写

匹配流程：

  1. 首先在所有非正则规则（=、普通前缀、^~）中确定匹配度最高的前缀；
  2. 然后按配置顺序匹配正则规则，任一正则命中即直接采用正则结果；
  3. 若正则均未命中，则采用第 1 步确定的前缀规则；
  4. 若命中 ^~ 规则，则直接采用，不再执行正则匹配。

静态资源性能调优

指令 作用 生效前提
sendfile 文件传输走内核零拷贝，减少用户态拷贝 处理静态文件
tcp_nopush 数据包攒满后再发送，减少小包数量 需开启 sendfile
tcp_nodelay 有数据立即发送，降低延迟 需开启 keep-alive

说明：tcp_nopush 与 tcp_nodelay 看似矛盾（一个聚合发包、一个即时发包），但 Linux 2.5.9 之后两者可以共存：绝大多数数据包被聚合后发送，最后一个不足整包的数据由 tcp_nodelay 强制立即发出，兼顾吞吐与实时性。

gzip 压缩

原理

gzip 对文本类资源进行压缩后传输，浏览器收到后自动解压，可有效降低传输体积、节省带宽、提升加载速度。

常用指令

指令 作用 建议
gzip on 功能总开关 on
gzip_types 指定压缩的 MIME 类型 按需列出 text/css、application/javascript 等
gzip_comp_level 压缩级别 1~9 6（级别越高 CPU 开销越大）
gzip_min_length 低于该大小的内容不压缩 1024
gzip_buffers 压缩缓冲区数量与大小 4 16K
gzip_http_version 触发压缩的最低 HTTP 版本 1.1
gzip_vary 响应头携带 Vary: Accept-Encoding on
gzip_disable 指定浏览器 UA 不压缩 "MSIE [1-6]\."
gzip_proxied 反向代理场景是否压缩后端响应 按需

gzip 与 sendfile 的关系

sendfile 追求文件不经用户进程直接发送，而 gzip 压缩必须在用户进程内完成，二者直接同时启用时 gzip 可能无法生效。解决方案是启用 gzip_static：预先以 gzip 生成同名 .gz 文件（如 jquery.js.gz），Nginx 检测到后直接发送预压缩文件，兼顾传输效率与压缩效果。

跨域问题（CORS）

同源策略

浏览器规定：协议、域名、端口三者完全一致才视为同源。页面通过 Ajax 访问不同源的接口即构成跨域，浏览器默认拦截响应。

Nginx 解决方案

Access-Control-Allow-Origin 可指定具体域名（多个以逗号分隔），也可使用 * 表示全部来源；对安全性要求较高时应使用白名单方式。

防盗链

原理

浏览器请求资源时通常携带 Referer 请求头，标识请求来源页面。Nginx 依据 Referer 判断是否为信任来源，非信任来源则拒绝访问。
