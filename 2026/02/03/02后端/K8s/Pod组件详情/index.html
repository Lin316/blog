Pod 组件 yaml 配置

Pod 组件 yaml 配置详情

容器 imagePullPolicy 配置

注：如果镜像的 tag 有具体的版本号，那么 imagePullPolicy 默认值为：IfNotPresent。

​ 如果镜像的 tag 是 latest，那么 imagePullPolicy 默认值为：always。

imagePullPolicy 取值 拉取策略
Always 只用远程仓库的镜像创建容器
IfNotPresent 如果本地仓库有镜像，就用本地仓库的镜像创建容器，如果本地仓库没有镜像，就用远程仓库的镜像创建容器。
Never 只使用本地仓库的镜像创建容器，如果本地仓库没有镜像，就报错。

容器 command 配置

command 用来配置容器的启动命令，如果yaml 配置了 command，那么 Dockerfile 的 CMD 启动命令配置就不会生效，以 command 配置的启动命令为准。

容器 resources 配置

limits：用于配置容器运行时最多可以占用的资源，当容器占用的资源超过上限时会被终止，并进行重启。

requests：用于配置运行容器最少需要的资源，如果资源没有达到最低要求，容器无法启动。

cpu：配置 CPU 的核心数，可以为整数或小数。

memory：配置内存大小，单位可以选 Gi、Mi、G、M。

容器 ports 配置

ports 用来声明容器的端口信息。需要说明的是：ports 只是描述信息，并不会真正开放端口，容器能否被访问由容器内应用决定。

配置项 说明
name 端口名称，同一个 Pod 内必须唯一
containerPort 容器端口，即容器内应用监听的端口
protocol 端口协议，可选 TCP、UDP、SCTP，默认为 TCP
hostPort 把容器端口映射到宿主机端口，通过 节点IP:hostPort 访问，不推荐使用

说明：

  • 即使不配置 ports，容器也可以正常被访问，ports 主要起描述作用，方便 kubectl describe 等工具展示。
  • 容器端口只在 Pod 内部和集群内有效，想对外提供服务需要借助 Service。
  • hostPort 会把端口映射到宿主机，同一节点同一端口只能有一个 Pod，容易冲突，生产环境一般用 Service 的 NodePort 代替。

Pod 生命周期

Pod 生命周期：创建 Pod、运行初始化容器、运行主容器、终止 Pod。

Pod 在生命周期中会出现的5种状态：

  • 挂起（Pending）：Pod 已被创建，但还没被调度到节点运行，例如拉取容器镜像时。
  • 运行中（Running）：pod 成功被调度到节点上，并且至少有一个容器正在启动或者正在运行。
  • 成功（Succeeded）：pod 内的所有容器都正常退出，例如一次性任务成功执行结束。
  • 失败（Failed）：pod 内的所有容器都已终止，但至少有一个容器异常终止，比如逻辑报错、内存溢出等。
  • 未知（Unknown）：无法获取 pod 状态，通常由网络通信失败导致的。

Pod 创建和终止流程

初始化容器

初始化容器是一种在主容器启动前执行的特殊容器，用于完成一次性的准备工作。

初始化容器的特点：

  • 顺序执行：初始化容器需要按顺序执行，只有上一个初始容器执行成功了，才会执行下一个初始化容器。
  • 必须全部执行成功：只要有一个初始化容器执行失败，pod 会重启，主容器不会启动。
  • 只执行一次：每次创建 pod 的时候都会执行一次，执行完成后会退出，不会长期运行。

初始化容器的作用：

  • 准备运行环境：下载依赖包、解压文件、生成配置、初始化数据库脚本。
  • 注入主容器缺少的工具：例如 curl、bash 等通过共享 Volume 提供给主容器使用。
  • 等待依赖服务就绪：如等待下游服务启动后再启动主容器。

Pod 调度

Pod 调度就是决定 Pod 运行在集群中的哪个节点上。默认情况下由 kube-scheduler 自动调度，也可以通过配置指定调度方式。调度方式主要分为三种：定向调度、亲和性调度、污点与容忍。

定向调度

定向调度是直接在 Pod 上指定要调度到哪个节点，分为 nodeName 和 nodeSelector 两种。

nodeName

通过 nodeName 直接指定 Pod 运行在哪个节点上。通常用于测试或调试场景，生产环境一般不用，因为如果该节点故障，Pod 也无法在其他节点重建。

亲和性调度

定向调度是硬性指定，如果没有满足条件的节点，Pod 就无法运行。亲和性调度更灵活，分为三种：

  • nodeAffinity（node 亲和性）：决定 Pod 倾向于调度到哪些节点。
  • podAffinity（pod 亲和性）：让 Pod 和指定标签的 Pod 调度到同一个拓扑域（如同一个节点）。
  • podAntiAffinity（pod 反亲和性）：让 Pod 和指定标签的 Pod 调度到不同的拓扑域，例如将多副本打散到不同节点，提高服务高可用性。

亲和性都支持两种限制：

  • requiredDuringSchedulingIgnoredDuringExecution：硬限制，节点必须满足条件才能调度。
  • preferredDuringSchedulingIgnoredDuringExecution：软限制，优先调度到满足条件的节点，没有满足条件的节点也能调度到其他节点，weight 权重范围 1-100，越大优先级越高。

操作符（operator）的取值：

operator 说明
In 标签值在给定的 values 列表中
NotIn 标签值不在给定的 values 列表中
Exists 只要存在该 key 的标签即匹配，不需要配置 values
DoesNotExist 不存在该 key 的标签即匹配，不需要配置 values
Gt 标签值大于给定的数值，只支持 nodeAffinity
Lt 标签值小于给定的数值，只支持 nodeAffinity

注意：Gt 和 Lt 只支持 nodeAffinity，且 values 只能写一个整数；podAffinity 和 podAntiAffinity 只支持 In、NotIn、Exists、DoesNotExist。

污点与容忍

污点（Taint）是站在节点角度设置的属性，用来拒绝 Pod 调度到该节点；容忍（Toleration）是站在 Pod 角度设置的属性，用来忽略节点上的污点。污点格式为 key=value:effect，effect 有三种：

  • PreferNoSchedule：尽量不把 Pod 调度过来，没有其他节点时也会调度。
  • NoSchedule：不调度新的 Pod 过来，不影响节点上已有的 Pod。
  • NoExecute：不调度新的 Pod 过来，同时驱逐节点上已有的 Pod。
